# BetterGI 0.64.0 PT-BR Integration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Incorporate the official BetterGI `0.64.0` release into the stacked PT-BR UI and OCR branches without losing localization behavior, then publish refreshed PRs and a verified Windows x64 executable without merging either PR.

**Architecture:** Merge the immutable official `0.64.0` tag into the UI base branch first, then merge that updated base into the OCR branch. Preserve upstream release behavior and assets; keep semantic OCR matching only where the PT-BR branch replaces language-specific gates. Resolve the single predicted content conflict by adopting upstream's visual chat-exit flow while retaining localized Serenitea Pot recognition elsewhere.

**Tech Stack:** C# 12, .NET 8, WPF/MVVM, Newtonsoft.Json, xUnit, PowerShell audit scripts, Git/GitHub CLI.

**Spec:** `Docs/superpowers/specs/2026-08-21-pt-br-ocr-automation-design.md`

## Global Constraints

- Preserve Portuguese (Brazil), Simplified/Traditional Chinese, English, French, and Japanese recognition behavior.
- Preserve the installed `User/I18n/pt-BR.json` file when no online PT-BR update exists.
- Treat official tag `0.64.0` (`f0cd4fe90d22e9b1fcb3f6b4b61fe6131773410e`) as the upstream release source.
- Keep PR #3 stacked on `i18n/pt-br-completo`; do not merge either PR automatically.
- Use exact-path staging only; never use `git add .` or `git add -A`.
- Require Windows Release x64 build success and a clean language-dependent OCR audit before publication.
